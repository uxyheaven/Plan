# 《AI分析洞察》对外分享报告 · 提纲（待确认版）

> 用途：由 `outline.md`（30 分钟演讲稿）转制为「HTML 报告 + 讲者系统演示」配套报告。
> 本提纲只做结构与取舍规划，三组对照仅占位、不填内容，等你确认后再开始制作。

---

## 0. 一句话定位

**报告不是演讲稿的图文版，而是演讲的"视觉骨架 + 证据载体"。**
凡是"只能靠嘴说才成立"的内容（停顿、互动、话术）不放进报告；凡是"听众需要看着才能记住/判断"的内容（四个词、四项功能、三组对照、四步流程）做成报告主体。

**主张句（全篇唯一核心命题）：在 AI 时代，业务和 IT 缺一不可。**

---

## 1. 全篇叙事主线

一条"从熟悉到陌生、从现象到机制"的单向推进链，**每一段都只回答一个问题，并自然带出下一段的问题**：

| 段落 | 回答的问题 | 留给下一段的问题 |
|---|---|---|
| ① 开场 | 我们想让 AI 帮什么？ | 现在的数据工具能到哪一步？ |
| ② 体检表 | 数据在哪看、怎么看？ | 哪些变化值得关注、说明了什么？ |
| ③ 三组对照 | AI 的分析到底好在哪？ | 这些分析放在哪儿能用？ |
| ④ 体检表 AI 功能 | 日常使用中怎么用起来？ | 这些分析依据是怎么准备的？ |
| ⑤ 微决策（上） | 分析前要准备什么？ | 准备好之后怎么用？ |
| ⑥ 微决策（下） | 怎么变成可执行、可复用的任务？ | 你打算从哪个问题开始？ |
| ⑦ 结尾 | 回到三个期待，谁来做？ | —— |

**主线逻辑**：先立三个期待 → 先用大家熟悉的工具（体检表）建立共同语言 → 再用实证（对照）让人自己得出判断 → 再落到"你明天能用"（AI 功能） → 最后才解释背后的机制（微决策）→ 收束回三个期待，发出参与邀请。

**为什么机制放在后面而不是前面**：微决策是"后台系统"，先讲机制会让业务同事在前 10 分钟失去抓手。演讲顺序是"现象 → 实证 → 机制"，报告沿用这个顺序不变，只把口播内容视觉化。

---

## 2. 建议呈现顺序与逐部分取舍

### ① 开场｜建议 3 屏

- **作用**：立靶子（三个期待）+ 点痛点 + 亮主张。三问要在结尾被回扣，是结构上的闭环扣子，不可省。
- **纳入**
  - 破冰三问 → 视觉化为三张卡片：**更懂业务 / 分析更准确 / 重复工作更省力**。理由：口头提问改成视觉呈现后，现场仍可口头追问，但报告读者也能自明。
  - 导入痛点 → 三段式："数据多 → 找重点难 → 光看数字难判断"。
  - 主题主张："在 AI 时代，业务和 IT 缺一不可"。
  - 讲者身份 → **只保留与本题相关的一句**（负责公司经营分析系统 / 此前负责卡片平台）。理由：可信度来自"我做过什么与本题相关"，不是履历长度。
- **舍弃**
  - 破冰的互动编排（"停顿，等回应'想'"）→ 纯口语装置，书面化即失效。
  - 个人履历细节：90% 自研前端通过卡片实现、企划指标体系、技术部数据化项目 → 与本次主题无关，移入讲者备注或尾页一句话。
- **衔接**：三问不做解答，直接进体检表——"先看现在的数据工具能到哪一步"。

### ② 体检表：经营数据的日常入口｜建议 5–6 屏

- **作用**：把听众拉进熟悉场景，建立共同语言和共同词汇。
- **纳入**
  - 是什么 / 为什么：指标体系是数据化经营基础 → 公司、部门两级体检表 → 明年延伸到团队和个人（体现路径感）。
  - **四个词（全篇第一记忆点）**：追达成、看预警、找问题、明责任 → 做成四宫格。
  - 四个功能各一屏：**四比**（比自己 / 目标 / 市场 / 标杆）、**三灯**（红黄绿）、**查口径·看趋势·下钻**、**责任到部门→团队→个人**。
  - 两个具体例证：ROE 考核口径（剔除永续债）、考核净利润与 CIR 的下钻方向。理由：具体的口径例子最能证明"这不是概念演示"。
  - "关键问题"记录栏 → 保留，它是后面 AI 分析的落点。
- **舍弃**
  - 管理层原话（"何总也提出…"）→ **建议脱敏**为"公司管理层要求各级干部多看多用数据…"。理由：对外分享不宜出现具名内部表述。
  - 权限申请指引（"没有权限联系业管或财企老师"）→ 移入附录或口播。
  - "先切到 2025 年 11 月"等演示指令 → 转为【截图位·待补】。
- **衔接**：末句停在疑问上——"有了数据和工具，还要判断：这一期哪些变化值得关注、说明了什么？" → 引出 AI。

### ③ 三组分析对照｜建议 6–7 屏（核心证据段，见第 3 节）

- **作用**：全篇的证据核心。让业务同事自己判断，而不是讲者断言"我们的 AI 更好"。
- **纳入**
  - 三组对照的**统一结构**（每组一屏）。
  - 点评机制说明：请业务同事判断"哪份更有帮助、好在哪、还缺什么"。
  - **点评三问作为侧栏提示条**：哪一句有用/需核实？接下来会看哪个指标？两份都没提到什么？理由：这三问是全篇最有迁移价值的方法，值得留在报告里供读者复用。
  - 小结一屏：说明两种生成方式与输入差异（若用 A/B 标记，此时揭示）。
- **舍弃**
  - 逐字点评话术（"这一组请××帮忙看看…"）与现场编排 → 讲者工具，不入报告。
  - "无人回应时由讲者点评"等兜底安排 → 讲者备注。
- **衔接**："回到体检表，看看这些 AI 分析具体放在哪里。"

### ④ 体检表 AI 功能｜建议 4 屏

- **作用**：把"AI 有用"落到"你明天在哪能用"。
- **纳入**：四项功能，严格按**整体 → 局部 → 主动提醒**的顺序展示：经营概览 / 模块解读 / 单指标解读 / 异常推送。
- **舍弃**：操作路径口播（"打开体检表…"）→ 截图位替代；这一节基本无冗余，是源稿信息密度最高的部分之一。
- **衔接**："这些分析所需的数据、口径和业务知识，是怎么准备的？" → 由现象转入机制。

### ⑤ 微决策（上）：分析前要准备什么｜建议 4–5 屏

- **作用**：回答"凭什么"，把前面展示的效果归因到可复用的准备工作的。
- **纳入**
  - 为什么需要：光给数据不够，还要说明口径、指标关系、业务背景，且要能复用。
  - **四步流程**（需新制流程图）：准备数据和知识 → 确定分析主题 → 配置场景和计划 → 查看及使用结果。
  - 业务建模五项：数据集 / 实体管理 / 指标管理 / 维度管理 / 指标关系图 → 一张结构图 + 截图位。
  - 业务知识：知识管理 → 补充业务背景、规则、经验。
  - **"业务同事的参与重点：确认口径、关系和业务背景是否准确"** → 做成高亮提示条。理由：这是结尾参与邀请的伏笔。
- **舍弃**
  - 逐个菜单的口播式介绍（"打开业务建模，随页面简要介绍各菜单"）→ 改为一张图，避免报告变成系统说明书。
- **衔接**："准备好以后，怎样把它们用到具体的分析任务中？"

### ⑥ 微决策（下）：从准备到应用｜建议 4–5 屏

- **作用**：从"准备了什么"推进到"怎么跑起来、怎么迭代"。
- **纳入**：主题（确定分析范围）/ 三类场景（分析洞察、指标解读、异常预警）/ 执行计划（频次与时间）/ 查看结果与结合反馈调整。
- **一处顺序修正**：源稿口播顺序是"分析洞察 → 异常预警 → 指标解读"（口语习惯所致），**报告按"分析洞察 → 指标解读 → 异常预警"编排**，即关注范围由大到小：一组指标 → 单个指标 → 持续监控。理由：报告要体现结构，口播的错位不必继承。
- **舍弃**：三类场景的口播开场白 → 改为三栏对照卡片（各自回答什么问题、谁来配置、产出什么）。
- **衔接**："这样，准备好的数据和知识就用到了具体任务中" → 直接进结尾总回顾。

### ⑦ 结尾｜建议 2 屏

- **作用**：回扣、升维、发出可执行的邀请。
- **纳入**
  - 一句话总回顾（体检表 → 对照 → 微决策）。
  - **三问回扣**：更懂业务 / 更准确 / 更省力 → 分别对应"业务带经验进来"和"IT 把数据和工具准备好"。
  - 主张句复现："业务和 IT 缺一不可"。
  - 参与邀请（保留原话的行动性）："如果大家手上有一个每周、每月都要反复分析的问题，欢迎会后找我。"
  - **金句作为封底**：让业务经验成为 AI 的分析依据，让每一次分析成为下一次的积累。
- **舍弃**：口头致谢；问答环节（另见下）。

## 3. 三组对照的预留结构【对照1】【对照2】【对照3】

**统一模板**（每组一屏，三组共用同一视觉骨架，便于横向比较）：

```
【对照N】
· 业务问题：______（一句话，业务同事熟悉的表述）
· 期间与口径：______ / ______
· 分析 A：______（生成方式 + 输入）
· 分析 B：______（生成方式 + 输入）
· 点评维度：哪份更有帮助 / 好在哪 / 还缺什么
· 本组小结：______
```

**三组的分工（建议按"可信度 → 边界 → 行动"递进）**：

- **【对照1】作用：建立可信度（第一印象）**
  - 位置：三组之首，决定听众是否愿意继续信。
  - 选什么：业务同事**最熟悉**、两份结果**差异最直观**的问题（例如某模块当期表现的归因）。
  - 要什么效果：让人一眼看出差距，自己说出"这份更有用"，而不是听你讲。
- **【对照2】作用：暴露能力边界**
  - 位置：中间，负责把讨论从"AI 能不能"推进到"AI 差在哪、还缺什么"。
  - 选什么：**更依赖口径/维度/指标关系知识**的复杂问题（例如跨指标归因、需要剔除特殊因素的判断）。
  - 要什么效果：引出"业务知识必须补进来"这一结论，为第 ⑤ 段微决策做铺垫。
- **【对照3】作用：落到可复制与行动号召**
  - 位置：最后，直接服务结尾的参与邀请。
  - 选什么：**每月/每周重复做**的常规分析，展示被配置和复用后的效果。
  - 要什么效果：让听众对号入座——"我手上就有这样一个问题"，为结尾"欢迎会后找我"提供具体落点。

**三组的共同作用**：完成"实证 → 边界 → 行动"的论证链，让第 ⑤⑥ 段的机制解释有据可依，而不是凭空介绍系统。

## 4. 整体舍弃清单（不进报告）

- **时间轴与时长分配**（00:00—30:00、各段分钟数）：报告无现场计时需求 → 转为内部分量参考（见第 6 节篇幅配比）。
- **问答环节及其内容清单**：非报告内容。如需要，末页可加一栏"会后联系/常见问题"，待你决定是否保留。
- **所有演示动作指令**（【进入系统】【悬停】【点击】【打开菜单】）：→ 统一替换为【截图位·待补】标记。
- **参考区全部条目**：含本地绝对路径与会话链接，属内部信息 → 不进对外报告。
- **逐字讲稿与话术**：保留为讲者备注，不进报告正文。
- **每一段的"回顾与转场"口播**：→ 压缩为报告中的一句**小结条 + 转场问句**，不重复正文内容。

## 7. 需要你确认的 4 个决策点

1. **脱敏程度**：内部系统名（BOAT）、具体指标名（ROE / 考核净利润 / CIR）、管理层称谓、截图中的真实数据——是否保留原样，还是需要脱敏处理？
2. **报告形态**：单页滚动 HTML / 分页式 HTML / 直接做成 PPT？这影响对照段的排版方式。
3. **讲者备注**：是否需要在报告中另出一份"讲者版"（含话术与演示动作提示），与外发版分离？
4. **对照段信息**：三组对照的**业务问题领域**是否已有初步方向？如有，可先在提纲里把每组的定位写得更具体。

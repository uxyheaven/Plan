## Slide 1: 证券公司 AI 经分系统宏观方案

- Key points:
  - 核心判断：AI 经分系统应定位为经营管理闭环，而不是新一代报表平台。
  - 管理价值：把分散经营事实转化为可预警、可行动、可复盘的经营判断。
  - 汇报目的：明确建设方向、优先场景、组织配套和后续需拍板事项。
- Visual idea: 高管汇报标题页，抽象证券经营网络与决策闭环作为轻量背景。
- Layout role and intent: cover，建立主题和管理视角。
- Required source images: none.

## Slide 2: 核心闭环：从经营事实到经营智能

- Key points:
  - 核心链路为“数据 -> 知识 -> 分析 -> 预警 -> 建议 -> 动作跟踪 -> 自我进化”。
  - 管理含义：从看见事实，升级为解释变化、提前干预、推动动作、沉淀经验。
  - 高管关注点：系统是否真正进入经营节奏，而不是停留在展示层。
- Visual idea: 横向或环形七段闭环流程图，每段配一个简短经营问题。
- Layout role and intent: concept explanation，给后续结构建立总框架。
- Required source images: none.

## Slide 3: 目标对象：让不同层级形成统一经营语言

- Key points:
  - 高管层需要快速判断全局态势、关键风险和战略机会。
  - 条线与分支机构需要识别资源配置问题、短板诊断和增长抓手。
  - 一线团队需要具体、合规、可执行的客户和服务动作建议。
  - 经分与战略团队要从取数制表转向洞察审核、经营解释和方法沉淀。
- Visual idea: 金字塔或组织层级视图，展示高管、条线、分支、一线、经分运营的不同需求。
- Layout role and intent: audience / stakeholder map，说明系统服务对象和价值分层。
- Required source images: none.

## Slide 4: 数据层与知识层：可信事实 + 证券经营理解

- Key points:
  - 管理前提：指标口径不统一，AI 输出就没有公信力。
  - 数据层要整合客户、账户、交易、产品、渠道、组织、市场和风控合规事实。
  - 知识层要沉淀指标定义、业务逻辑、管理规则、客户分层、市场解释和合规边界。
  - 关键决策：先统一公司级经营语言，再逐步支持条线和区域差异化。
- Visual idea: 双层底座图，底层为数据域矩阵，上层为知识资产模块。
- Layout role and intent: architecture / foundation，说明系统可信度来源。
- Required source images: none.

## Slide 5: 分析层：把数据组织成经营判断

- Key points:
  - 分析层的目标不是回答“数是多少”，而是回答“问题在哪里、为什么、影响多大、谁负责、下一步看什么”。
  - 典型方向包括全局态势、异动归因、机构对比、客户结构、产品经营、渠道效率、市场影响和专项复盘。
  - 输出结构应稳定为“现象 -> 影响 -> 原因 -> 证据 -> 建议方向 -> 责任对象”。
  - 高管价值：把经营会议从解释数据转向讨论决策。
- Visual idea: 中央为“经营判断”，四周围绕分析方向和证据链步骤。
- Layout role and intent: analytical framework，说明洞察生产方式。
- Required source images: none.

## Slide 6: 预警与建议：从提前干预到可执行动作

- Key points:
  - 预警不只是红黄绿灯，而要说明触发原因、影响对象、责任人和处理时限。
  - 预警覆盖经营目标、客户流失、机构表现、产品风险、市场冲击、合规边界和经营机会。
  - 建议分为管理建议、业务建议和一线建议。
  - 治理原则：AI 给出建议和依据，人负责确认、取舍、授权和执行。
- Visual idea: 左侧为预警分级漏斗，右侧为建议转动作的卡片链路。
- Layout role and intent: process / governance，强调风险机会识别与人机边界。
- Required source images: none.

## Slide 7: 动作跟踪与自我进化：让系统越用越懂公司

- Key points:
  - 没有动作跟踪，系统只能证明“说得对”；有动作跟踪，才能证明“是否改善经营”。
  - 跟踪内容覆盖建议来源、责任组织、执行计划、过程记录、指标变化和复盘结论。
  - 自我进化沉淀指标、预警、建议、知识、场景和组织打法。
  - 管理机制：系统学习、人工审核、稳定发布，避免自动改规则带来管理和合规风险。
- Visual idea: 闭环后半段放大图，展示任务流、反馈流和知识沉淀流。
- Layout role and intent: closed-loop execution，说明系统如何从分析工具变成管理机制。
- Required source images: none.

## Slide 8: 典型经营场景：从驾驶舱到专项复盘

- Key points:
  - 建议先从高管可感知、组织可执行、成效可复盘的场景切入。
  - 公司经营驾驶舱：目标达成、关键波动、重大风险和战略机会。
  - 分支机构经营诊断与客户资产流失分析：识别短板、流失原因和合规挽留动作。
  - 产品销售与持仓分析、专项战役复盘：关注增长质量、客户体验和打法复制。
- Visual idea: 五个场景模块组成的经营场景地图。
- Layout role and intent: scenario map，展示优先落地场景。
- Required source images: none.

## Slide 9: 组织协同与关键原则

- Key points:
  - 三类角色：经营决策者、业务专家、经分运营者。
  - 三类流程：日常监控、周度经营分析、月度复盘迭代。
  - 落地原则：经营闭环优先、人机分工清晰、证据链完整、合规边界内生。
  - 组织要求：让 AI 洞察进入经营会议、任务分派和复盘机制。
- Visual idea: 角色 x 流程矩阵，旁边列出关键原则。
- Layout role and intent: operating model，说明系统真正落地所需的组织配套。
- Required source images: none.

## Slide 10: 分阶段建设路径与讨论重点

- Key points:
  - 第一阶段统一看见：指标口径、看板、基础问数和高频报告。
  - 第二阶段自动分析：场景模板、异动归因、机构对比和证据链。
  - 第三阶段主动预警：预警体系、责任分派和处理时限。
  - 第四阶段动作闭环，第五阶段持续进化，形成公司级经营智能资产。
  - 需高管拍板：首发经营问题、统一指标、预警责任、AI 建议边界、动作跟踪范围和成效衡量方式。
- Visual idea: 五阶段路线图，下方列出需要管理层拍板的讨论问题。
- Layout role and intent: roadmap / closing，收束为建设路径和下一步决策。
- Required source images: none.
